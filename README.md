# TASK02 — Git: локальний + віддалений репозиторій

Опис команд, використаних для створення локального репозиторію, його наповнення та синхронізації з віддаленим репозиторієм на GitHub.

## Ініціалізація локального репозиторію

```
git init
```
Створює порожній git-репозиторій у поточній папці.

```
git branch -M main
```
Перейменовує основну гілку в `main` тому що стандартна назва "master" 

## Налаштування автора 

```
git config --global user.email "romanfilonenko06022007@gmail.com"
git config --global user.name "RomaFil"
```
Git вимагає ім'я та email автора перед першим комітом — без цього `git commit` завершується помилкою `Author identity unknown`.

## Наповнення локального репозиторію

```
git add .
```
Додає всі файли в поточній папці до індексу (staging area).

```
git commit -m "Added test file"
```
Фіксує зміни в історії репозиторію (перший, "root"-коміт).

## Підключення віддаленого репозиторію

```
git remote add origin https://github.com/RomaFil/TASK02.git
```
Прив'язує локальний репозиторій до віддаленого на GitHub під іменем `origin`.

## Синхронізація

```
git fetch --all
```
Завантажує дані (коміти, гілки) з віддаленого репозиторію, не змінюючи робочу копію.

```
git pull origin main --allow-unrelated-histories
```
Підтягує та об'єднує (merge) віддалену гілку `main` з локальною. Прапорець `--allow-unrelated-histories` обов'язковий, бо локальний і віддалений репозиторій створювались незалежно один від одного і не мають спільного коміту-предка.

```
git push origin main
```
Відправляє змерджений результат (локальні + підтягнуті з GitHub зміни) назад у віддалений репозиторій — після цього обидва репозиторії мають однаковий вміст.

## Додавання README.md у репозиторій

```
git add .
git commit -m "Add README"
git push origin main
```
Додає README.md в індекс, фіксує коміт і відправляє на GitHub.

## .gitignore

Файл, що вказує Git, які файли/папки не відстежувати (тимчасові файли ОС, налаштування редактора, логи, локальний конфіг ініціалізації):
```
.DS_Store
Thumbs.db
.vscode/
.idea/
*.log
.git_myconfig
```

## utils/git_init.sh — скрипт ініціалізації локального репозиторію

Універсальний bash-скрипт, що автоматизує базові налаштування нового Git-репозиторію: `git init`, `git config --local user.name/user.email/init.defaultBranch` та підключення remote-репозиторію. Персональні дані (ім'я, email, назва гілки) у скрипті не зашиті — зчитуються з окремого, не закоміченого файлу `.git_myconfig` у директорії, звідки запускається скрипт (корінь проєктів).

**Формат `.git_myconfig`:**
```
USER_NAME="YOUR NAME"
USER_EMAIL="example@net.com"
USER_BRANCH="main"
```

**Формати запуску:**
```
cd ~/projects/
./work_git/utils/git_init.sh                                         # довідка / створення конфігу
./work_git/utils/git_init.sh new_git                                 # створити й ініціалізувати репозиторій new_git
./work_git/utils/git_init.sh new_git https://github.com/user/repo.git  # те саме + підключити remote
```

**Логіка роботи:**
- 0 параметрів → довідка (`usage`); за відсутності `.git_myconfig` спершу пропонує створити його в діалоговому режимі.
- 1 параметр (назва директорії) → створює директорію (якщо не існує), ініціалізує репозиторій, застосовує локальні `git config`, створює README.md з назвою проєкту; якщо директорія вже репозиторій або непорожня — виводить повідомлення й не чіпає її.
- 2 параметри (назва директорії + remote URL) → те саме + `git remote add origin`; якщо директорія вже репозиторій — лише додає remote; якщо містить чужі файли й не є репозиторієм — завершує роботу з повідомленням.
- Захист: відмовляє в роботі, якщо параметрів більше 2, або якщо сам скрипт запущено зсередини вже існуючого Git-репозиторію (а не з кореня директорії проєктів).
